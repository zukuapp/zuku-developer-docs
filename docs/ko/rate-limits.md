# 요청 한도

> 정책 버전: 2026-10-01 · API v1

ZUKU에는 성격이 다른 두 종류의 한도가 있습니다.

- API 요청 한도: 요금제·요청 종류별로 짧은 구간의 호출 속도를 제한합니다.
- CLI 게시 한도: `--yolo` 프로덕션 게시를 계정당 최근 6시간 동안 성공 3회로 제한합니다.

## CLI 게시 한도 (`--yolo`)

| 항목 | 값 |
|---|---|
| 대상 | `zuku deploy … --yolo`, `zuku agent … --yolo`의 프로덕션 게시 |
| 한도 | ZUKU 계정당 최근 6시간(롤링) 동안 성공한 게시 3회 |
| 강제 위치 | 서버. 다른 장치·동시 실행에도 같은 한도 |
| 초과 시 | `429 DEPLOY_QUOTA_EXCEEDED` + `Retry-After` |
| 한도를 쓰지 않는 것 | 초안 생성, 업로드, 실패하거나 거부된 게시, 같은 계정·콘텐츠·패키지 SHA-256의 재확인 |
| 한도를 차지하는 것 | 성공한 게시, 결과가 아직 확정되지 않은 예약 |

```sh
zuku account --quota
```

`used`(성공 수), `pending`(미확정 수), `remaining`(남은 수), `reset_at`(회복 시점), `retry_after`(대기 시간)를 보여 줍니다.

`zuku agent --yolo`는 모델을 호출하기 전에 남은 한도를 확인합니다. 한도가 0이면 모델 사용량을 쓰지 않고 바로 끝납니다. 게시 결과가 불명확하면 자동으로 다시 게시하지 않습니다. 확인 방법은 [패키징과 게시](cli/publishing.md)와 [게임 개발 에이전트](cli/agent.md)에 있습니다.

## 요금제별 기본 한도

각 수치는 60초 동안 허용하는 요청 수입니다. 로그인 사용자는 계정별로 계산하므로 탭·기기·API 키를 늘려도 계정 한도는 늘어나지 않습니다. 비회원은 IP를 기준으로 계산합니다.

| 요금제 | 조회 `read` | 변경 `write` | 플랫폼 페이지 `platform` | 업로드·게시 `upload` | AI 시작 `ai` | Cloud `cloud` |
|---|---:|---:|---:|---:|---:|---:|
| 비회원 `guest` | 240 | 30 | 120 | 3 | 2 | 180 |
| Free `free` | 600 | 120 | 240 | 12 | 6 | 600 |
| Super ZUKU `super_zuku` | 1,200 | 240 | 360 | 24 | 12 | 1,200 |
| Creator `creator` | 1,800 | 360 | 480 | 60 | 20 | 1,800 |
| Cloud Pro `cloud_pro` | 3,000 | 600 | 720 | 120 | 30 | 2,400 |
| Cloud Scale `cloud_scale` | 6,000 | 1,200 | 1,200 | 240 | 60 | 12,000 |
| Game Dedicated `cloud_dedicated` | 12,000 | 2,400 | 1,800 | 480 | 120 | 30,000 |

`game_dedicated`는 서버에서 `cloud_dedicated`로 정규화합니다. 표의 수치는 호출 속도 한도이며, 비회원 `upload`·`ai` 값이 업로드나 유료 기능 사용 권한을 뜻하지는 않습니다. 로그인·권한·잔액·게시 조건은 각 API에서 따로 검증합니다. CLI 게시 한도는 이 표의 `upload` 한도와 별도로 적용됩니다.

게임 Cloud 브리지는 초당 최대 6회, 동시 요청 3개로 제한됩니다.

## 요청 종류

| 종류 | 적용 예 |
|---|---|
| `read` | 일반 GET/HEAD, 콘텐츠·댓글 조회, AI·변환 작업 상태 확인 |
| `write` | 좋아요·댓글·계정 작업 외 일반 변경, 편집·저장 |
| `platform` | ZUKU 페이지 탐색 |
| `upload` | 파일 업로드, 콘텐츠 생성·게시, 가져오기·빌드·변환 시작 |
| `ai` | AI 실행·채팅 시작, 번역 요청 |
| `cloud` | Cloud 프로젝트 API, 게임 런타임 요청 |
| `auth` | 로그인·가입·캡차·Passkey 등 인증 경로 |

일반 API는 해당 종류의 한도를 사용합니다. AI 상태 조회는 AI 시작 횟수를 쓰지 않습니다.

## 10초 구간과 인증 한도

조회·페이지·변경·업로드·AI에는 10초 고정 구간도 적용합니다. 기본값은 분당 한도의 1/3을 올림한 값이며, 조회·페이지는 최소 20회, 변경은 최소 3회, 업로드·AI는 최소 1회입니다. Cloud에는 10초 제한을 적용하지 않습니다. 인증은 요금제와 관계없이 10초당 20회입니다.

인증은 모든 유료 요금제에서도 로그인 계정당 30회/분입니다. 비회원 인증은 IP당 120회/분이며, 기존 로그인 실패·MFA 잠금·일회용 인증 검증 조건이 더 엄격하면 그 조건이 우선합니다.

민감한 인증 요청은 대상별로도 제한합니다. 로그인 이메일과 핸들이 같은 계정을 가리키면 하나의 대상 한도를 씁니다. 이 조건은 요금제와 관계없이 적용됩니다.

| 인증 대상 조건 | 허용 횟수 | 구간 |
|---|---:|---:|
| 로그인 대상 | 10 | 10분 |
| 회원가입 대상 | 5 | 15분 |
| 아이디 찾기·비밀번호 복구 요청 대상 | 5 | 15분 |
| 비밀번호 재설정 증명 확인 | 10 | 5분 |

인증 본문이 16 KiB를 넘으면 처리 전에 거절합니다. 일반 `/auth/me`·세션 목록 조회는 `read`, 프로필 편집은 `write`로 계산하므로 인증 시도 한도를 쓰지 않습니다.

## IP 합산 보호

로그인 계정에도 공유 IP에서 과도하게 합산된 요청을 막는 별도 보호 한도를 적용합니다.

| IP 합산 보호 | 요청/분 |
|---|---:|
| 조회 | 20,000 |
| 변경 | 5,000 |
| 페이지 | 6,000 |
| 업로드·게시 | 1,200 |
| AI 시작 | 600 |
| Cloud | 60,000 |
| 인증 | 600 |
| 모든 종류 합계 | 90,000 |

공유망의 비회원은 하나의 IP 한도를 함께 씁니다. 로그인하면 계정별 기본 한도를 쓰며 IP 합산 보호는 계속 적용됩니다. IP 합산 보호와 10초 제한은 요금제를 바꿔도 해제되지 않습니다.

## API 키 한도

공개 API의 `X-API-Key`에는 [`/developer/keys`](authentication.md#개발자-api-키)에서 발급한 사용자 키를 사용합니다. 이 키에는 추가로 키당 600회/분의 기본 한도가 적용됩니다. 여러 키는 소유 계정의 공통 한도를 함께 소비합니다.

Cloud의 월 사용량·무료 포함량·QoS·지출 한도·AI 제공자 제한은 이 속도 제한과 별개입니다. 속도 한도를 통과해도 사용량이나 비용 조건을 충족하지 않으면 작업이 거절됩니다.

## 응답 헤더와 재시도

제한 대상 요청에는 다음 헤더가 붙습니다. 성공 응답은 해당 종류의 기본 60초 구간을, `429`는 거절한 조건의 구간을 나타냅니다.

| 헤더 | 의미 |
|---|---|
| `X-RateLimit-Limit` | 표시된 구간의 허용 횟수 |
| `X-RateLimit-Remaining` | 이 요청 이후 남은 횟수 |
| `X-RateLimit-Reset` | 구간 종료 Unix epoch 초 |
| `X-RateLimit-Window` | 구간 길이(초) |
| `X-RateLimit-Scope` | 요청 종류 또는 거절한 IP·키 보호 종류 |
| `X-RateLimit-Plan` | 서버가 검증한 요금제(IP 보호에서 인증 확인 전이면 `unknown`) |
| `Retry-After` | `429`에서 다시 시도할 때까지 기다릴 초 |

이 헤더는 제한 대상 요청에만 붙습니다. 헬스 확인·OPTIONS·정적 자산 등은 제외 요청입니다. 남은 횟수는 한 종류의 한도만 나타냅니다. 다른 한도는 별도로 적용됩니다.

```json
{
  "success": false,
  "error": {
    "code": "RATE_LIMITED",
    "message": "요청이 잠시 몰렸어요. 표시된 시간이 지난 뒤 다시 시도해 주세요.",
    "details": {
      "plan": "free",
      "scope": "read",
      "limit": 600,
      "remaining": 0,
      "window_seconds": 60,
      "retry_after_seconds": 12,
      "reset_at": 1790812860,
      "upgrade_available": true
    }
  }
}
```

클라이언트는 실제 `Retry-After`를 우선합니다. 값이 없으면 Reset 안내나 제한을 반환한 서비스의 오류 메시지를 따릅니다. 폴링은 잠시 멈추고, 여러 작업은 큐로 분산합니다. POST·결제·업로드·AI 생성·게시 요청은 자동으로 반복하지 않습니다. 먼저 작업 상태와 기존 멱등성 계약을 확인합니다. 카운터를 확인할 수 없으면 API는 `503 RATE_LIMIT_UNAVAILABLE`과 재시도 안내를 반환합니다.

오류 코드 전체는 [오류와 응답 형식](errors.md)에 있습니다.

## 정책 조회 API

`GET /api/v1/rate-limits/policy`는 요금제 표, IP 합산 보호, 10초 구간 규칙, API 키 기본값을 반환합니다. 인증 없이 조회하며 요청 카운터를 쓰지 않습니다.
